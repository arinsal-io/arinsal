# ERTS BeamAsm Reference Assembly for Benchmark Kernels

This directory contains reference native machine code generated by Erlang/OTP 29.1.1 (ERTS 17.1) BeamAsm JIT on Apple Silicon (macOS arm64 / Apple M1 Pro) for `.agents/gates/kb/kernels.erl`.

Artifacts in this directory:
- [kernels.asm](kernels.asm): Machine disassembly dumped by `erl +JDdump true` containing all functions in `kernels.erl`.
- [beam_asm_global.asm](beam_asm_global.asm): Machine disassembly of the shared global runtime fragments emitted by BeamAsm.
- [README.md](README.md): This report detailing instruction counts, hot loops, BEAM opcode annotations, and global fragment calls.

---

## 1. Investigation: Why the Initial Attempt Crashed

The supervisor's initial attempt to run `erl +JDdump true` crashed with:
```
Runtime terminating during boot ({undef,[{kernels,module_info,[],[]}...]})
Crash dump is being written to: erl_crash.dump...done
```
and produced no `kernels.asm`.

### Root Cause Analysis
1. **Boot Failure in `-eval`**: BeamAsm generates `<module>.asm` files at the exact moment a module is loaded into the emulator. When passing `-eval` during startup, any unhandled exception (e.g. attempting to invoke `kernels:module_info()` before compiling `kernels.erl`, omitting `-pa` pointing to where `kernels.beam` is located, or a failed pattern match in `-eval`) causes `init:start_it` to fail during boot.
2. In Erlang, fatal failures during boot trigger `erl_crash.dump` generation and terminate the emulator immediately before user modules can be loaded. Because `kernels` was never loaded, BeamAsm never compiled it, leaving no `kernels.asm`.
3. **OTP Module Pollution**: By default, `erl +JDdump true` dumps `.asm` files for *every* module loaded, including ~110 core OTP modules (`application.asm`, `lists.asm`, `maps.asm`, `gen_server.asm`, etc.) into the current working directory.
4. **Clean Reproduction**:
   - First compile: `erlc -o tmp/dump .agents/gates/kb/kernels.erl`
   - Then run from an isolated directory: `erl +JDdump true -pa . -noshell -eval 'kernels:module_info(), erlang:halt(0).'`
   - *(Alternative)*: ERTS also has an undocumented runtime flag defined in `erts/emulator/beam/erl_bif_info.c:5413-5432`: `erlang:system_flag(jit_asm_dump, true)` which toggles dumping dynamically to prevent dumping all of OTP.

## 2. ERTS BeamAsm AArch64 Register & Calling Conventions

From `erts/emulator/beam/jit/arm/beam_asm.hpp`:

| Register | ERTS Name | Purpose |
| :--- | :--- | :--- |
| `x19` | `scheduler_registers` | Points to scheduler registers struct (`x_reg_array`) |
| `x20` | `E` | Erlang process stack pointer |
| `x21` | `c_p` | Pointer to current `Process` struct |
| `w22` | `FCALLS` | Reduction counter (decremented on function entry and return) |
| `x23` | `HTOP` | Process young generation heap top pointer |
| `x24` | `active_code_ix` | Active code index for module/export dispatch |
| `x25` | `XREG0` | Erlang X register 0 / function argument 1 / return value |
| `x26` | `XREG1` | Erlang X register 1 / function argument 2 |
| `x27` | `XREG2` | Erlang X register 2 / function argument 3 |
| `x28` | Scratch / XREG3 | Temporary calculation register |
| `x30` | `LR` | Link register |

Tagging representation on 64-bit ERTS:
- Primary tag bits: lowest 4 bits (`0xF` = `15` denotes Small Integer `_TAG_IMMED2_SMALL`).
- Small integer value: `(Value << 4) | 0xF`.
  - `0` is represented as `15` (`0x0F`).
  - `1` is represented as `31` (`0x1F`).
  - `2` is represented as `47` (`0x2F`).
- Pointer tags: Primary header / boxed tag is `0x2` (`0b0010`).

### 3.3 `tuple_loop/3`

Erlang source:
```erlang
tuple_loop(0, _Tuple, Sum) -> Sum;
tuple_loop(N, Tuple, Sum) ->
    Next = setelement(2, Tuple, N),
    tuple_loop(N - 1, Next, Sum + element(2, Next)).
```

#### Instruction Counts
- **Total Function Body**: **54 instructions** (plus 1 `bl` in `func_info` header).
- **Hot Loop Iteration**: **29 instructions** executed per loop iteration (steady-state, tuple in young generation, small-int fast paths).

#### Key BeamAsm Optimization: In-Place Tuple Update (`update_record_in_place_IsdI`)
BeamAsm emits code that dynamically detects whether `Tuple` resides in the young generation heap (`HTOP` vs `high_water`). When true, instead of allocating a fresh tuple on every iteration, it updates the slot **directly in place** (`str x25, [x2, 16]`), avoiding all heap allocations!

#### Hot Loop Instructions Annotated by BEAM Op

```asm
tuple_loop/3:
# --- i_breakpoint_trampoline ---
    str x30, [x20, -8]!       ; Push LR onto Erlang stack
    b L71
L71:
# --- i_test_yield ---
    adr x2, tuple_loop/3
    subs w22, w22, 1
    b.le L37                  ; Yield check (not taken)

# --- is_eq_exact_fss ---
    cmp x25, 15               ; Check if N == 0 (tagged 0 = 15)
    b.ne @label_15-4          ; If N != 0, branch to loop body (taken)

@label_15-4:
label_15:
# --- test_heap_It ---
    add x2, x23, 64           ; Check 64 bytes heap headroom
    cmp x2, x20
    b.ls L73                  ; Headroom available (taken)
L73:
# --- update_record_in_place_IsdI ---
    and x2, x26, -8           ; Untag Tuple pointer (tag = 2)
    ldr x3, [x21, 480]        ; Load c_p->high_water boundary
    cmp x2, x23               ; Compare tuple pointer against HTOP
    ccmp x2, x3, 0, 5         ; Check if tuple is in young generation
    b.hs L74                  ; In young gen: take fast in-place update path! (taken)
    ; [copy fallback using NEON q30, q31 omitted]
L74:
    str x25, [x2, 16]         ; Mutate Element 2 in-place (offset 16: header + elem1 + elem2)
    add x26, x2, 2            ; Retag Tuple pointer as Next (tag = 2)

# --- i_minus_jIssd (N - 1) ---
    mov x2, 31
    subs x0, x25, 16
    and x8, x25, 15
    ccmp x8, 15, 0, 9
    b.eq L75                  ; Fast path (taken)
L75:
    mov x25, x0               ; N = N - 1

# --- load_tuple_ptr_s ---
    and x0, x26, -8           ; Untag Next tuple pointer

# --- i_get_tuple_element_sPS ---
    ldr x28, [x0, 16]         ; Load element(2, Next) directly from offset 16

# --- i_plus_jIssd (Sum + Element 2) ---
    and x8, x28, -16          ; Untag element 2 value
    adds x0, x27, x8          ; Sum + element 2
    and x8, x27, x28
    and x8, x8, 15
    ccmp x8, 15, 0, 9
    b.eq L76                  ; Fast path (taken)
L76:
    mov x27, x0               ; Sum = Sum + element 2

# --- i_call_only_f (Tail Call) ---
    ldr x30, [x20], 8         ; Pop LR
    b tuple_loop/3            ; Loop back to entry
```

#### Key BeamAsm Optimization: Match Context Reuse
On function entry, `i_bs_start_match3_Stjd` tests `cmp x9, 293` (`HEADER_SUB_BITS | ERL_SUB_BITS_FLAGS_MATCH_CONTEXT`). If the argument is already a match context (as it is on all tail-recursive iterations), it skips allocation and branches directly to `L87`, zeroing allocation overhead.

    b.lo @label_22-7          ; Branch if insufficient bits (not taken)

## 5. Architectural Comparison: ERTS BeamAsm vs. Arinsal JIT

As measured in [REPORT.md](../REPORT.md), ERTS achieves **1.68 ns / iteration** on `tail_loop/2` compared to Arinsal JIT's **19.5 ns / iteration**:

1. **Tight In-Place Native Loop**:
   ERTS BeamAsm loops directly with `b tail_loop/2` across 21 pure native instructions. No stack frames are allocated, no veneers are created, and no foreign-function interfaces are crossed during steady-state execution.
2. **Zero Syscall / Memory Allocation Overhead**:
   ERTS compiles machine code once at module load time into executable memory buffers. It does not invoke `mmap`, `munmap`, or invalidate instruction caches per yield slice.
3. **Register-Mapped Reductions & Execution State**:
   ERTS dedicates `w22` for `FCALLS`, `x20` for stack `E`, and `x23` for heap `HTOP`. Yield checking is a single `subs w22, w22, 1` followed by `b.le L37`.
4. **Fast-Path Arithmetic with Conditional Compare (`ccmp`)**:
   Tagged small integer arithmetic (`i_minus_jIssd` / `i_plus_jIssd`) computes arithmetic untagged/tagged results and validates tags and overflow concurrently in 4–5 instructions (`subs`, `and`, `ccmp x8, 15, 0, 9`, `b.eq`) without touching the C runtime unless an actual bignum overflow occurs.
